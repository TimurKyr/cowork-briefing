# Мой день

Персональный дашборд-PWA: открываешь иконку на телефоне и видишь план дня
(таймлайн с живым маркером «сейчас»), чеклист и дедлайны. Можно листать дни
вперёд/назад. **Никакого агента и фоновых задач — сайт читает всё сам из браузера.**

**Три источника данных (все — прямо из браузера):**
- **События дня** — Google Calendar API. Сайт запрашивает несколько публичных
  календарей (список в `config.js`), склеивает события за выбранный день и
  сортирует. `kind`/цвет берутся от календаря-источника. Промежутки свободного
  времени (>2 ч между событиями) сайт считает сам.
- **Погода** (только для сегодня) — Open-Meteo, без ключа.
- **Задачи и дедлайны** — Supabase (Postgres + REST). Их читает и пишет браузер
  (галочки, добавление, приоритеты, перенос «с вчера»).

- **Фронтенд:** статический HTML/CSS/JS без фреймворков → GitHub Pages.
- **Ключи:** публичный **anon** ключ Supabase + **restricted** Google API-ключ
  (ограничен доменом сайта и включённым Calendar API). Оба коммитятся в
  `config.js` — это нормально, они публичны по назначению. `service_role`
  Supabase не используется нигде.
- **Время:** всё «сегодня/сейчас» считается по **Asia/Almaty (UTC+5)**, независимо
  от часового пояса устройства.

## Что умеет
- **Навигация по дням** — свайп влево/вправо на мобильном, стрелки `←/→` и кнопки
  `‹ ›` на десктопе, кнопка **«Сегодня»** для возврата. Маркер «сейчас», строка
  «сейчас/дальше» и погода — только когда открыт сегодняшний день.
- **Кнопка «Обновить»** (⟳) в шапке — перечитывает календарь и погоду заново; в
  футере видно время последнего обновления.
- **Таймлайн дня** с маркером «сейчас», локациями, промежутками «Свободно» и цветом
  по календарю. Если у события есть описание (Description), у блока появляется
  точка-намёк, а тап/клик открывает окно с текстом (крестик / фон / Esc — закрыть).
- **Чеклист** с оптимистичным UI; невыполненные дела с прошлых дат подтягиваются
  сразу и помечаются реальным возрастом («⤷ со вчера», «⤷ 5 дней назад»).
- **Приоритеты дел** — три группы (высокий / средний / низкий), перетаскивание за
  ручку между группами и внутри группы (мышь и палец), порядок сохраняется в базе.
- **Дедлайны** — постоянный список с обратным отсчётом и цветом срочности.
- **Светлая/тёмная тема** с переключателем; выбор запоминается.
- **Офлайн** — оболочка кэшируется (service worker), последнее состояние сегодня —
  в localStorage; открывается мгновенно и работает без сети.

| `app.js` | События — Google Calendar API, погода — Open-Meteo, `tasks`/`deadlines` — Supabase; навигация по дням, рендер, кэш, время по Алматы. |

## Пошаговая настройка

### 1. Supabase (задачи и дедлайны)
1. <https://supabase.com> → **New project** (имя, пароль базы, регион).
2. **Project Settings → API**: скопируй **Project URL** (`SUPABASE_URL`) и
   ключ **`anon` `public`** (`SUPABASE_ANON_KEY`). `service_role` **не трогай**.
3. **SQL Editor → New query**:
   - **Новая база:** вставь весь `schema.sql` и **Run** — появятся `tasks` и
     `deadlines` с RLS и политиками для `anon`.
   - **Была база прошлой версии:** прогони `migration.sql`, затем
     `migration-priority.sql`. Миграции идемпотентны.

### 2. Сделать календари публичными
Для каждого из четырёх календарей (Daily, Study, Work, Workout):
1. Google Calendar → навести на календарь → **⋮ → Настройки и общий доступ**.
2. Раздел **«Разрешения на доступ к мероприятиям»** → включить **«Сделать
   общедоступным»** → в выпадающем списке выбрать **«Просматривать все данные о
   мероприятиях»**. Без этого API-ключ (без OAuth) события не увидит.
3. Раздел **«Интеграция календаря»** → скопировать **Идентификатор календаря**
   (вида `c_…@group.calendar.google.com`) — он уже вписан в `config.js`, сверь.

### 3. Включить Google Calendar API на ключе
1. <https://console.cloud.google.com/> → выбери проект (тот же, где был ключ Drive).
2. **APIs & Services → Library** → найди **Google Calendar API** → **Enable**.
   (Если раньше ключ был ограничен только Drive API — добавь Calendar API в список.)
3. **APIs & Services → Credentials** → открой свой API-ключ:
   - **Application restrictions → HTTP referrers** → домен сайта, например
     `https://<логин>.github.io/*`.
   - **API restrictions** → должен включать **Google Calendar API**.
4. Значение ключа → это `CALENDAR_API_KEY`.

> Локально (`http://localhost`) события не загрузятся, если ключ ограничен только
> доменом Pages — это нормально. Хочешь тестировать локально — добавь
> `http://localhost:8000/*` в разрешённые referrers.

### 4. Заполнить `config.js`
```js
window.SUPABASE_URL = "https://xxxx.supabase.co";
window.SUPABASE_ANON_KEY = "sb_publishable_...";
window.CALENDAR_API_KEY = "AIza...";            // ключ с включённым Calendar API
window.CALENDARS = [ /* id, kind, colorId — см. пример */ ];
window.LAT = 51.16;  window.LON = 71.47;        // координаты города для погоды
window.APP_NAME = "Тимур";                       // имя в приветствии (можно "")
```
`colorId` у календарей — число 1–11 из палитры Google. Значения в конфиге
предположительные; открой сайт и сверь цвета блоков с цветами календарей, поправь.

### 5. Запушить и включить Pages
```bash
git add -A && git commit -m "..."
git push
```
GitHub → репозиторий → **Settings → Pages** → **Deploy from a branch** →
**main / (root)**. Через минуту сайт на `https://<логин>.github.io/<репозиторий>/`.

### 6. Добавить на домашний экран (iPhone)
Открой сайт в **Safari** → «Поделиться» → **«На экран Домой»**. Откроется на весь
экран без адресной строки. (Android/Chrome: меню → «Установить приложение».)

## Как это работает
- При открытии сайт берёт **сегодняшнюю дату по Алматы**, запрашивает события всех
  календарей за этот день (`calendar/v3/.../events` с `timeMin/timeMax` и
  `timeZone=Asia/Almaty`), склеивает их, добавляет промежутки «Свободно», и грузит
  погоду (Open-Meteo). Задачи и дедлайны — из Supabase.
- Листание дней (свайп/стрелки/кнопки) меняет просматриваемую дату и перечитывает
  календарь на неё. Для несегодняшних дней «сейчас», строка «сейчас/дальше» и
  погода не показываются — просто события и промежутки.
- Чеклист привязан к просматриваемой дате: для сегодня — задачи дня плюс
  невыполненные с прошлых дат; для других дней — задачи этой даты. **Дедлайны —
  общий постоянный список**, показывается на всех днях (отсчёт всегда от сегодня).
- Тап по делу/дедлайну и формы добавления пишут в Supabase (оптимистичный UI).
- Пустой день (нет событий) — стейт «На этот день событий нет».

> **Обновление оболочки.** Файлы оболочки кэширует service worker. Если правишь
> `index.html`/`app.js`/`sw.js` — подними версию кеша в `sw.js` (`myday-shell-vN`),
> иначе установленная PWA останется на старой версии.

## Замечание про безопасность
Данные Supabase защищены только тем, что URL и anon-ключ известны лишь тебе;
политики RLS дают `anon` полный доступ к `tasks`/`deadlines` — осознанный выбор
для личного дашборда без своего сервера, не храни там ничего чувствительного.
Google-ключ ограничен по домену и API, но **календари публичны** («просматривать
все данные о мероприятиях») — любой, кто знает ID календаря, сможет прочитать
события. Не держи в этих календарях приватного, что не должно быть доступно по
прямой ссылке.
